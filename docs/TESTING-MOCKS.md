# MSW Mock Layer (offline integration tests)

Phase 1 of the integration program: a Mock Service Worker layer that lets component and data-layer tests run the **real** supabase-js client — through the **real** `src/lib/db.ts` contract — against an in-memory PostgREST emulation, fully offline. It complements the live suites in [`docs/TESTING.md`](TESTING.md); it never replaces them (the RLS suite remains the only proof that the *actual* security wall holds).

## How it works

`src/lib/supabase.ts` creates supabase-js **without a custom fetch**, so all PostgREST / GoTrue / edge-function traffic goes through `globalThis.fetch` — exactly what MSW's node server intercepts. `src/lib/fivemanage.ts` uses a bare `fetch` too. Nothing in the app changes; the mock layer sits entirely underneath it.

| Piece | Path | Role |
| --- | --- | --- |
| Handlers | `src/mocks/handlers/` | PostgREST tables (catch-all + filter engine), RPC (typed, representative set), GoTrue password-grant auth, FiveManage uploads, edge functions |
| Store | `src/mocks/store.ts` | in-memory rows + scenario switches; reset between tests |
| Fixtures | `src/mocks/fixtures/` | row builders returning **complete `Tables<'…'>` Rows** + `roleSession()` + case bundles |
| Scenarios | `src/mocks/scenarios.ts` | one-import surface: data builders + network/permission shaping |
| Node server | `src/mocks/server.ts` | vitest entry (started by `tests/msw/setup.ts`) |
| Browser worker | `src/mocks/browser.ts` | reserved for the Storybook phase — inert, see below |
| Suite | `tests/msw/` | the `msw` vitest project (happy-dom), part of plain `npm test` |

Run it with `npm test` (both projects) or `npx vitest run --project msw`. The suite is fully offline and needs no secrets — forks and `main` stay green.

## What the handlers emulate (and what db.ts observes)

The mock reproduces the **wire contract** `src/lib/db.ts` documents, not the whole of PostgREST:

- reads → JSON arrays (object shape under `Accept: vnd.pgrst.object+json`); `Prefer: count=exact` → `Content-Range` for `countRows()`;
- `insert()` → `Prefer: return=representation` echo (201);
- **zero-row update = RLS-blocked** — an UPDATE/DELETE the policy filters matches nothing: success status, empty representation, **no error**. `data.length === 0` is the only blocked-write signal, and `updateNoSelect()` (`return=minimal`, 204) cannot see it — both faithfully mocked;
- RLS INSERT is the loud exception (403 / `42501` row-level-security violation); revoked grants are loud on every verb (403 / `42501`);
- filter surface: `eq` / `is` / `in` / `or=(…ilike…)` (what `ilikeAny()` emits) / `order(.nullsfirst)` / `limit` / `select` projection. A query shape beyond that means the parser in `src/mocks/handlers/postgrest.ts` needs extending — it will fail loudly, never silently.

Server-authoritative RPCs (sign-off, roster) are **deliberately not re-implemented** — pin an outcome with `rpcResult(fn, value)`; unknown RPCs answer PostgREST's real 404 `PGRST202` so a spec that needs a new handler fails loudly.

Where a plan phase ships a *contract* (return shapes + refusal semantics), the handlers answer that contract from the mock DB without becoming a second server: `handlers/legal.ts` (Phase 4) and `handlers/reports.ts` (Phase 5 — the template catalog seeded from `src/lib/forms.ts` with the migration's `review_required` rule and `REQUIRED` map, `report_template_save / publish / discard / update`, `report_create / submit / review / finalize / reopen`, `report_entities_set`, `report_record_export`, `case_task_waive / unwaive`). Row-returning RPCs **raise** (a `ReportRpcError` → PostgREST 400 with the server's message) exactly where the server raises — missing required fields, the `case_closure` open-task gate, a reopen without a reason, a review-required template on `report_finalize`; the jsonb RPCs answer `{ok:false, code:'denied', message}` for authority refusals and raise only on hard validation (a malformed schema, an unreadable ref). The four Phase 5 tables are RPC-only (every write → 403 / `42501`), templates read for active members, entities / exports read through the parent report, and a direct PATCH of `reports` runs the `block_direct_report_finalize` mirror (`reportUpdateGuard`: workflow columns refused, `fields` locked once submitted / sealed, 403 / `P0403`) while a direct INSERT is pinned to the published version (`pinReportTemplateVersion`). `handlers/reports.test.ts` pins all of it.

`handlers/intel.ts` (Phase 6) answers the intel-triage contract the same way. The read wall is `private.field_submission_readable` (the author, or an active member unless the record is `siu_sensitive` — then the SIB agent, played by the Owner as in `entity.ts`, the referrer or the assignee) and `visibleIntelRows` applies it to `field_submissions` (drafts are the author's alone), the realtime shadow `field_submission_events`, `intel_groups` / `intel_group_members` / `intel_group_cases`, the reviewer notes, the officer thread, verdicts and links. The RPCs — `field_submission_reject / restore / comment / validate / counts / decide / grade / assign / ask / siu_refer`, `field_claim_decide / link`, `field_submission_convert`, `intel_group_create / add / remove / link_case / unlink_case / close / reopen / suggest / summary`, `siu_referred_submissions` — **raise** an `IntelRpcError` where the server raises: `P0403` for an authority refusal (`private.perm_raise` — 'not authorized', 'that record is not in your jurisdiction', 'only a Bureau Lead or above can restore a rejected record'), `P0001` for a validation one ('say why this is being rejected', 'validate every claim and grade the source first (n of m claims decided, source ungraded)', 'that record is already in this group', 'the lead record stays in its group — close the group instead', 'a person claim cannot be linked to a narcotic' / 'cannot become a narcotic', 'already linked'); a void RPC answers 204. `field_submission_convert` answers jsonb (`{ok:false, code:'denied'}`, `{ok:false, code:'duplicate', matches}` from `entityDuplicates`, `{ok:true, id, kind}` with `source_submission_id` stamped and the claim linked) and `intel_group_suggest` / `intel_group_summary` return the contract's shapes. Notifications mirror `private.intel_notify` — a MINIMAL payload (`submission_id / submission_no / jurisdiction / actor_id / actor_name` plus the kind's key; never summary, details, reason or title), never the actor, a test actor never reaching a real target, one unread per kind per record — for `intel_new` (a send: command + Owner inside the wall), `intel_assigned`, `intel_question` (the submitter), `intel_reply` (the assignee, else the reviewer who asked) and `intel_referred` (agents, never the referrer). The shadow table is maintained by `afterFieldSubmissionChange` (the mock's AFTER trigger: no row for a draft or a deleted record). The client-facing triggers are mirrored on the PostgREST path: a direct INSERT into `field_submissions` runs `stampFieldSubmission` (the author is the session, a record starts as `draft` or `new`, the number is issued on send), a direct PATCH runs `fieldSubmissionPatch` (`block_direct_intel_review_columns` — a sent record refuses every client UPDATE with 'that record has already been sent; the review state only changes through the review actions', a draft its review / SIB / grade columns, 400 / `P0001`; a draft is the author's editor and a send is numbered; the reject reason and validation note are not row columns — the text lives in the note and the audit row) and a POST to `field_submission_messages` runs the narrowed policy (the submitter's own reply while `needs_info`, else 403 / `42501`). The four new tables take no client writes (403 / `42501`) and the notes table no INSERT. `handlers/intel.test.ts` pins all of it.

`handlers/action.ts` (Phase 7) answers the Action Center + scheduler contract (scratch `p7_contract.md` §1–§3) the same way. Three RPC-only tables read behind their own walls through `visibleActionRows` — `action_item_state` for its `user_id` only, `action_escalation_rules` for the Owner (the four seeded rules — `signoff` 72 h, `access_request` 48 h, `task_overdue` 48 h, `legal` 120 h disabled — are seeded lazily by `ensureActionRules()` on the first read or RPC, like the report templates), `action_escalations` with the case's visibility (`canReadCaseAs`; an `access_request` row only for `canGrantCase`) — and refuse every write (403 / `42501`). The Phase 7 RPCs have **explicit routes** (`/rest/v1/rpc/<fn>`, registered before the generic rpc catch-all and honouring the same `offline` / `slowNetwork` / `rpcResult` switches): `action_item_set_state` / `_many` implement `private.action_key_class` (`actionKeyClass` — the dismissable / decision / work prefix lists, `:expiry`, `case:%:followup`, `case:%:signoff-decide`) and **raise** an `ActionRpcError` where the server raises — `P0403` for an authority refusal ('your account is not active', 'this item is a decision or assigned work — decide it, finish it or snooze it'), `P0001` for validation ('that queue item key is not valid', 'unknown state operation', 'snooze for up to 48 hours', 'at most 100 items at a time'), `23514` for the key-shape CHECK (`KEY_SHAPE`); the bulk call skips and reports a non-dismissable dismiss; a decision snooze writes `ACTION_ITEM_SNOOZED` (`{key, until}` single, ONE `{keys, until}` bulk). `notifications_mark_read` flips the session's own unread rows and stamps `read_at` (the trigger mirror lives in the RPC — a direct PATCH of `notifications.read` is not mirrored); `notification_resolve` answers the first 100 ids (no raise), resolves the payload subject in the contract's order (report → task → blocker → submission → request → case; ids cast tolerantly — a non-uuid is no subject; a report is labelled by its `kind`) under the mock's own read walls and answers `visible=false, label=null` for an unreadable one and `subject_kind=null, visible=false` when the payload names no uuid subject. `action_reassign_task` / `_blocker` check, in the server's order, `canGrantCase` (lead or any Bureau Lead / Deputy / Director) + the archived case **before** the row's state ('already closed' / 'already resolved'), then the reason (≥ 3), `userCanAccessCase` (active and command role / lead / creator / bureau / JTF / a live grant) and the same holder, write `assignee` / `owner_id`, audit `TASK_REASSIGNED` / `BLOCKER_REASSIGNED` and notify through `actionNotify` — the `private.action_notify` mirror: skip null / self / no profile, a test actor never reaches a real target, one unread per (type, `task_id ?? blocker_id ?? source_id ?? case_id`) per hour, `actor_id` / `actor_name` only with a session, the text keys (incl. `note`) stripped, an inactive target skipped, `true` only when a row was written. `action_escalation_run` / `action_escalation_rule_set` answer `{ok:false, code:'denied', message}` to everyone but the Owner; the sweep (`actionEscalationSweep(onlyCase?)`) evaluates the three rules over the seeded rows (sign-off by stage → Deputies / Directors / Owners; pending access requests → the case bureau's leads + Deputies; overdue tasks → the case lead, or the bureau's leads when the lead is the assignee), filters every recipient through `userCanAccessCase`, opens or re-opens one ledger row per (kind, source) with its `stage` (a sign-off row whose stage moved on is resolved first), notifies `action_escalated {kind, source_id, case_id, case_number}` only on that (re)opening (the case creator is the guard actor), records only the recipients written in `notified`, audits `ACTION_ESCALATED` with no actor and resolves closed sources; the Owner's run adds the `scheduled_job_runs` row and `ACTION_ESCALATION_RUN`; `rls_test_escalation_run(p_case)` is the fixture-scoped runner (an `rls-test-…@cidportal.test` session, a case created by such a profile — 'caller is not a test fixture' / 'case is not fixture-owned' otherwise). `handlers/action.test.ts` pins all of it.

`handlers/trash.ts` (Phase 8) answers `trash_list(p_kind, p_limit)` / `trash_count()` (scratch `p8_contract.md` §1) from the mock store's soft-deleted rows — explicit routes registered before the generic rpc catch-all, the same `offline` / `slowNetwork` / `rpcResult` switches. The vocabulary is **imported** (`SOFT_DELETE_KIND` from `@/lib/db`, inverted to kind → table), so the 27 kinds cannot drift from the client. A row (`deleted_at != null` on any of those tables; a policy-denied table contributes nothing) is kept only when the session could restore it — `canRestoreAs`, the mock's reading of `private.perm_registry_delete` behind `perm_dispatch('restore')`: the Owner everything; a `case` → command with case access; a report / media / evidence / RICO row → command with case access; a task / blocker / note / message → its author (`created_by` / `author_id` / `uploaded_by`) or command, with case access; an intel link / case link → case access; the core registries → command; a narcotic → the Owner; a person–place / –vehicle / –relationship link → command or its creator; an account link → any active member; a signed-out or inactive caller → zero rows. Case access is `canReadCaseAs` (reports.ts) evaluated **as if the case were live**, so a deleted case's children stay listed exactly as the server lists them (and `rpc.ts`'s `restore_record` is what a real client would then call — the mock restore does not model `parent_deleted`; pin it with `rpcResult` when a screen needs it). The row shape follows the server: `label` by the fallback order case_number → name → plate → title → label → item_code → value → code → the id; `case_id` from the table (the case itself, the row's `case_id`, the RICO parent's case — `trashCaseIdOf`); `case_number` and `deleted_by_name` joined from `cases` / `profiles` (null when absent); `restorable` always true for a returned row; `permanently_deletable` = the session is the Owner. `p_kind` is trimmed and lower-cased; an unknown kind **raises** (`TrashRpcError` → PostgREST 400 `P0001` 'unknown record kind') before any row is read; `p_limit` is clamped 1–500 and applied after the newest-first sort; `trash_count` is the size of the list counted to 100 (`TRASH_COUNT_CAP` — the badge's 99+); a `media` row with `restricted` true is the Owner's alone (the review fix). `handlers/trash.test.ts` pins all of it (19 tests).

`handlers/ci.ts` (the Confidential Informant compartment) answers every `ci_*` RPC of scratch `ci_contract.md` §3 from the mock store with the contract's one rule — `canAccessCiAs(ci, profile) = hasFullCiAccessAs(profile) || ciIsActiveHandlerAs(ci, profile)` (full = Owner / Bureau Lead / DD / Director / an active non-oversight `siu_memberships` row) — and the contract's discipline: an unauthorized read is `null` / `[]` (never a raise or a `denied`), an authority refusal raises `CiRpcError` with `P0403` (the same wording for an inaccessible and an unknown CI), a validation refusal returns `{ok:false, code, message}` with the fixed strings exported as `CI_MESSAGES` (`unavailable`, the two `capacity` wordings, `primary_required`, `unsanitized`). The fourteen RPC-only tables (`CI_RPC_ONLY_TABLES`) read through `visibleCiRows` (the generic table handler runs the CI tables through it) and refuse every POST / PATCH / DELETE with 403 / `42501`. Capacity is derived exactly as the server derives it (`ciCapacityOf` = 6 unless a live override, `ciActiveCountOf`); an override audits `CI_CAPACITY_OVERRIDE` after the CI exists so `ci_audit_list(ci)` lists it. Audit goes to `ci_audit_events` only — `ci.test.ts` asserts `audit_log` stays empty; notifications go through `actionNotify` (ids only, portal-only kinds); `ci_events` is the ids-only shadow. Explicit routes are registered BEFORE the generic rpc catch-all (`handlers/index.ts`). Pinned by `src/mocks/handlers/ci.test.ts`.

## What it cannot mock: realtime

Supabase realtime is a WebSocket protocol — outside MSW's HTTP reach, and the app degrades gracefully without it. Live-update behavior is driven by the exported version store instead:

```ts
import { useRealtimeStore } from '@/lib/realtime'
useRealtimeStore.getState().bump('cases') // subscribed views refetch
```

Do not try to mock the realtime socket; bump the store.

## Fixtures and scenarios

Every row builder returns a **complete Row typed from `src/lib/database.types.ts`** — schema drift breaks `tsc --noEmit` in the fixtures instead of letting the mock layer fork into a parallel domain model. Compose, don't hardcode:

| Builder | Arranges |
| --- | --- |
| `roleSession(role, { division, active })` | seeded profile + GoTrue password-grant credentials for every role: `applicant` (inactive, JTF default), `detective` → `director`, `owner` (`is_owner` flag on a plain rank, like the live owner fixture) |
| `emptyCase()` / `populatedCase()` | fresh case / case with lead, reports, tasks, media, person, notification |
| `archivedCase()` | closed + `archived_at` set (invisible to the app's `is: { archived_at: null }` filter) |
| `legalHoldCase()` | active `legal_holds` row tied to a pending `legal_requests` DOJ submission |
| `restrictedMediaCase()` | public + `restricted` + archived media on one case |
| `slowNetwork(ms)` / `offline()` | latency on every response / network failure (note: postgrest-js retries network errors ~3×, ≈7 s, before surfacing) |
| `failedUpload(msg)` | FiveManage → HTTP 500 |
| `permissionDenied(table)` | revoked grant: every verb 403 / `42501` |
| `rlsRestricted(table)` | the silent wall: reads `[]`, UPDATE/DELETE zero-row, INSERT 403 |
| `rpcResult(fn, value)` | pin a (typed) RPC result |
| `reportTemplateRow()` / `reportTemplateVersionRow()` / `reportEntityRow()` / `reportExportRow()` | Phase 5 rows — a (typically retired) extra template + version, an inserted / mentioned record, an export receipt. The 14 seeded templates need no builder: `handlers/reports.ts` seeds them lazily (`ensureReportTemplates()` on the first read or report RPC), so an empty store answers like the migrated database |
| `fieldSubmissionRow({ officer_id })` / `fieldSubmissionPersonRow()` / `fieldSubmissionItemRow()` / `fieldClaimVerdictRow()` / `fieldClaimLinkRow()` / `fieldSubmissionReviewRow()` / `fieldSubmissionMessageRow()` / `fieldSubmissionEventRow()` / `intelGroupRow()` / `intelGroupMemberRow()` / `intelGroupCaseRow()` | Phase 6 rows — a sent, numbered intelligence record (`status: 'draft'` for a draft), its person / item claims, a verdict, a claim → registry link (one claim column, one target column), a reviewer note, a thread message, the realtime shadow row, a group with its members and linked cases. `handlers/intel.ts` uses the same builders when an RPC writes |
| `confidentialInformantRow({ person_id })` / `ciHandlerRow({ ci_id, user_id })` / `ciHandlerCapacityRow({ user_id, approved_by })` / `ciCapacityRequestRow({ requester_id })` / `ciIntelligenceRow({ ci_id, handler_id })` / `ciIntelligenceLinkRow` / `ciContactRow` / `ciAssessmentRow` / `ciPaymentRow` / `ciCaseLinkRow` / `caseIntelReleaseRow({ case_id })` / `ciReleaseRow` / `ciAuditEventRow({ id, action })` / `ciEventRow({ id, kind })` | the CI compartment's fourteen tables (`fixtures/rows.ts`) — most tests go through the RPCs (`ciCreate` …) instead, so the store is shaped exactly as the server would shape it |
| `actionItemStateRow({ user_id, dedupe_key })` / `actionEscalationRuleRow({ kind })` / `actionEscalationRow({ kind, source_id })` | Phase 7 rows — a viewer's queue memory for one key, an escalation rule (the four seeded ones need no builder — `handlers/action.ts` seeds them lazily), a ledger row the *Escalated* badge reads. `handlers/action.ts` uses the same builders when an RPC writes |

Everything resets between tests (`resetMockStore()` in `tests/msw/setup.ts`): rows, denials, sessions, latency, RPC overrides, deterministic ids.

**Adding a handler/fixture:** new table → usually nothing (the PostgREST catch-all serves any seeded table); new query shape → extend the parser in `handlers/postgrest.ts`; new read-RPC → add a typed case in `handlers/rpc.ts`; new domain rows → add a builder in `fixtures/rows.ts` returning a full `Tables<'…'>` Row and, if it's a recurring arrangement, a bundle in `fixtures/cases.ts` re-exported through `scenarios.ts`.

## Production-exclusion guarantees

The mock layer is dev/test-only by construction, and `tests/msw/production-exclusion.test.ts` proves it on every run:

1. **Static import graph** — no module under `src/app`, `src/components`, or `src/lib` imports `src/mocks` (scanned, not assumed). Only tests and the mock layer itself may.
2. **Build output sentinel** — every mocks module carries the `MSW_BUNDLE_SENTINEL` literal (`src/mocks/env.ts`); when a `.next/` build exists, every emitted JS chunk (and specifically the shared first-load set the bundle budget gates) is scanned for the sentinel and MSW's own markers. Self-skips without a build so offline runs stay green.
3. **No worker in `public/`** — `public/mockServiceWorker.js` is deliberately **not generated** (anything in `public/` ships verbatim). Browser mode is deferred to the Storybook phase, which must generate the worker into Storybook's own static dir — the test pins `public/` clean until then. `src/mocks/browser.ts` exists but is inert.
4. **Containment in tests** — the MSW server runs with `onUnhandledRequest: 'error'` and supabase-js is pointed at an unresolvable `.test` host (`tests/msw/env.ts`), so the suite can never reach a live project even if a handler is missing.

`npm run build` + `npm run check:bundle` stayed at the pre-MSW baseline (128.9 KB gzip shared first-load) — the layer adds zero bytes to production.

## Scenario coverage vs the program list

| Program scenario | Covered by |
| --- | --- |
| per-role sessions (applicant→owner, bureau, active flag) | `roleSession()` + `tests/msw/scenarios.test.ts` |

| degraded network (slow / offline) & failed upload | `tests/msw/scenarios.test.ts` |
| search / coverage reads (`search_all`, `doj_bureau_coverage`) | `handlers/rpc.ts` + `schema-fidelity.test.ts` |
| live updates | **not MSW** — `useRealtimeStore` bump (documented above) |
| component-through-mock smoke | `tests/msw/record-search-picker.test.tsx` (provider-light by design; auth-entangled views are Phase 2 harness work) |

What "green" here means: the app's data layer behaves correctly against a faithful wire contract. What it does **not** mean: the real policies enforce that contract — that is the live RLS suite's job, always.
